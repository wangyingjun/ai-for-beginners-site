# AI 入门站课程优化方案：先做实验，再讲概念

> 编写日期：2026-11-11（Asia/Shanghai）
> 范围：只做诊断和重设计，**不改代码、不推送**。
> 依据：仓库 `content/`、`app/lessons/[id]/page.tsx`、`components/demos/*`、`lib/ml/*`、测验题库；线上站 https://ai-for-beginners-site.vercel.app （2026-11-11 抓取 `/`、`/course`、`/lessons/01`、`/lessons/03`、`/lessons/04`）；另一个 bot 写的《课程叙事大纲》《交互动画与视频方案》《教案/》4 篇（`/home/box/shared/ai-for-beginners-site/`，2026-10-22）；Tier A 实测报告 `/workspace/aifb-validate/tier-a-report.md`。
> 用户原话：「课程还是不太能看得懂」「一上来的概念太多了，有没有那种小实验可以带演示的来说明」。

---

## 0. 一页结论

**核心原则：先做实验，后讲概念。**

每节课第一屏就是一个 **2–5 分钟、在浏览器里就能玩的小实验**，开场不出现任何术语。学习者先亲手做、亲眼看到现象，产生「咦？为什么会这样」的疑问，然后才给这个现象**起名字**。每节课**最多引入 1–2 个新术语**，公式和代码一律放到最后的「进阶」折叠区。

| 现在 | 改成 |
|---|---|
| 页面顺序：长篇机翻正文（历史、公式、代码）→ Demo → 48 个 cell 的静态 notebook | 页面顺序：**小实验** → 发生了什么（用大白话解释）→ 给现象起名字（1–2 个术语）→ 再玩一次（带任务）→ 3 道小测 → 一句话小结 → 进阶（公式 / notebook / Colab，默认折叠） |
| 25 课平铺，每课 2–4 小时，17 课属于 Tier B/C（要框架或 GPU） | 21 节核心**微课**（外加 1 个检查点），每节 20–30 分钟，核心路径**零安装、零代码**；框架课和重训练课移到「进阶 / 选修」 |
| Demo 是「自由玩的画布」，没有任务、没有引导 | Demo 改成**引导式实验**：预设数据、分步任务、自动检测「你做到了」、点出顿悟时刻 |

最划算的第一步：给现有 9 个 Demo 加 `preset` / `task` 参数，套上一个通用的 `<Experiment>` 引导外壳，然后先把第 03、04、05、07、14、18 课的开场换成实验（见 §6 的 P0）。

## 1. 为什么现在看不懂：诊断（附具体页面证据）

### 1.1 一上来概念太多：术语和公式比现象先出现

- **第 03 课 感知机**（`content/lessons/03/README.zh-CN.md`，约 3,300 字）：先讲 1957 年的历史，紧接着就是 `y(x)=f(wᵀx)`、阶跃函数、「感知机准则」`E(w)=-∑wᵀxᵢtᵢ`、梯度 `∇E(w)`、学习率 η，最后贴一段 Python。**在大约 1,500 字里引入了 7 个以上的新概念**（向量、转置、激活函数、准则、梯度、梯度下降、学习率），学习者还没看到过一条线是怎么「转」起来的。真正能让人看懂的感知机 Demo，被排在正文**之后**。
- **第 04 课 多层感知机**（README 约 2,900 字）：一节课里塞进损失函数（绝对 / 平方 / 0-1 / 对数）、softmax、参数 θ、梯度下降、小批量、SGD、非线性激活、链式法则偏导公式、计算图、反向传播，**大约 12 个术语**。配套的 `OwnFramework.ipynb` 前 20 个 cell 全是损失函数、对数损失推导和 softmax 类定义，第一次「训练」要到很后面才出现。
- **第 05 课 框架**：开场就是「张量、sigmoid、softmax、梯度、GPU、TPU、并行化、低级 API / 高级 API、计算图、Keras、PyTorch Lightning」，对零基础的人来说这是一张名词清单。
- **第 07 课 CNN**：「卷积滤波器、滤波核、加权平均、张量、层次特征、金字塔架构、VGG-16、top-5」，配图是 VGG-16 架构图。卷积核 Demo 同样排在正文后面。

### 1.2 先给数学和代码，后给直觉

- 课程正文和 notebook 里，公式（KaTeX / HTML 上下标）和 `import numpy` 总是先出现。第 03 课线上页面的 notebook 第一个代码 cell 是 `import pylab / ipywidgets / pickle / gzip`。
- 叙事大纲（2026-10-22）设计的是「Watch → Chapter → Demo → Notebook」，但**仓库里没有任何 watch / chapter 实现**（`content/media/` 不存在）。课页仍然是「正文 → Demo → Notebook」，教案没有落地。

### 1.3 缺前置知识，也没有学习路径

- 课程默认学习者会 Python、numpy、向量 / 点积、导数，但站内**从来没有补过这些前置**（上游 `0-course-setup` 只讲环境安装）。
- `/course` 页面只是 25 课平铺：只有「含 Notebook / Tier A/B/C / 实验」这类**工程标签**，没有「需要先会什么」「大约多久」「学完能做什么」，也没有「零基础从这里开始」。
- 首页还写着「当前为 Phase 1 MVP 脚手架……上游同步与 Supabase / Vercel 接线稍后进行」，看起来像没做完的站。

### 1.4 太依赖 notebook，太长

- 25 课里 **17 课属于 Tier B/C**（B 9 课、C 8 课，基本都要 PyTorch / TensorFlow 或 GPU），零基础学习者既跑不动，也读不懂。
- 很多课的 notebook 正文比课程正文还长：第 04 课 notebook 有 3,477 个汉字 + 27 个代码 cell，而 README 只有约 2,900 字；第 05 课的 3 本 notebook 加起来有 182 个 cell。也就是说，真正的「讲解」藏在 notebook 里，被代码和输出淹没了。
- 叙事大纲给出的单课时长是 **2–4.5 小时**（例如第 04 课 3–3.5 小时、第 18 课 3.5–4.5 小时），对自学的初学者来说太长，没有中途的成就感。
- Tier A 实测：Perceptron.ipynb 在浏览器里跑要 **147 秒**；Lab 的 `PerceptronMultiClass` 上游本身就是坏的（用了未定义的 `wts`）。

### 1.5 机翻残留、英文残留和坏链接（线上可见）

- 线上 `/lessons/04` 页面显示 **「TODO: 图片引用」**（上游原文残留）。
- 第 03 课 README 里的示例代码**是错的**：`weights = weights + eta*weights.shape`（应为 `eta*pos`），上游原样带过来了。
- 课内相对链接坏了：`lab/README.md`、`lab/PerceptronMultiClass.ipynb` 在线上 **404**；第 01 课还有 `../5-NLP/README.md` 这类上游目录链接。
- notebook 代码注释和图表标题大多是英文（如 `# pick the seed for reproducability`、`'Training data'`、`'Common loss functions for regression'`），输出里还能看到 `UserWarning: Matplotlib is currently using ...`。
- 外链多为英文：Wikipedia 34 处，docs.microsoft.com 和 towardsdatascience 共 17 处。
- 注意力 Demo 的预设句子是英文（`"the cat sat on the mat"`），对中文学习者不直观。
- 机翻腔重：「电位器是一种允许用户调整电路电阻的设备」这类旁注和学习目标无关。

### 1.6 Demo 和正文对不上，没有「任务」

- **颜色约定相反**：感知机 Demo 里 **蓝色 = +1、红色 = −1**；notebook 的 `plot_dataset` 里却是 **红色 = 正类**（`'r' if l>0 else 'b'`）。初学者会直接糊涂。
- 9 个 Demo 都是自由画布，组件只有 `locale / showFullscreenLink` 两个参数，**不能预设数据，不能布置任务，也不能判断学习者有没有看到关键现象**。比如感知机 Demo 没有 XOR 预设，「单层画不出弯边界」这个最重要的顿悟要靠学习者自己发现。
- 词向量 Demo 和注意力 Demo 用的是玩具数据，页面没有说明「这是示意」和真实模型的关系。

### 1.7 测验只考记忆，AI 助教门槛高

- 题库每套只有 3 题，而且多是记忆题，例如第 03 课课前测「早期的神经网络需要：手动调整权重 / 数 TB 的数据 / 特殊推理」，课后测「每一步会更新 ___：学习率 / 权重 / 梯度」。**没有解析**，也不考对现象的理解。
- 测验以正文里的链接形式出现，不在课页里内嵌。
- AI 助教要学习者**自己填写 LLM 的 API 地址和 Key**（`TutorSettingsForm`）。零基础用户基本会卡在这一步。

## 2. 设计原则

1. **实验先行**：每课第一屏就是实验，**开场 0 术语**。学习者要先「做一件事、看到一个现象」。
2. **先现象，后命名**：每课最多 **1–2 个新术语**，而且必须在学习者看到对应现象之后才出现，格式是「你刚才看到的 X，就叫 **Y**」。
3. **一节课只解决一个问题**：每节微课 20–30 分钟。原来的一课太长就拆成多节。
4. **公式和代码默认折叠**：核心路径零代码；「进阶」区放公式、notebook、Colab 和上游原文。
5. **中文语境的例子**：用外卖评分、垃圾短信、猜下一个字、成语接龙、手写数字这类身边的例子，不用医学肿瘤这类远离生活的例子。
6. **一致的视觉语言**：全站统一「正类 = 蓝 / 负类 = 橙红」、「误差 = 红色虚线」，Demo、插图、notebook overlay 都按这个约定。
7. **每课都有顿悟时刻**：实验必须设计出一个「反常现象」（线转不过去、温度一高就胡说、换个位置也能认出来），用这个反差驱动学习者往下看。

## 4. 标准课页模板（实验先行）

每节微课固定 7 段，前 4 段在 15 分钟内完成：

| 段 | 名称 | 时长 | 规则 | 复用组件 |
|---|---|---|---|---|
| ① | **先玩一下**（实验） | 3–5′ | 第一屏就是实验；只有一句任务说明，**不出现术语** | 现有 Demo + 新 `<Experiment>` 外壳 |
| ② | **你看到了什么？** | 2′ | 1 道「预测 / 观察」题（选择题），让学习者把现象说出来 | 新 `<ObserveQuestion>` |
| ③ | **发生了什么**（大白话 + 生活类比） | 3′ | 不超过 300 字；配 1 张动图或示意图 | Markdown overlay |
| ④ | **给它起个名字**（1–2 个术语） | 2′ | 术语卡：名字 + 一句话定义 + 指回刚才实验里的现象 | 新 `<TermCard>` |
| ⑤ | **再玩一次**（带任务） | 5′ | 2–3 个具体任务，完成后自动打勾；最后一个任务是「反常 / 失败」案例，用来引出下一课 | `<Experiment>` 任务模式 |
| ⑥ | **小测 + 小结** | 3′ | 3 道理解题，**每题带解析**；小结只有一句话，外加「下一课要解决的问题」 | 现有 `QuizPlayer`（加解析字段） |
| ⑦ | **进阶**（默认折叠） | 选读 | 公式、上游原文、notebook 静态输出、Colab / JupyterLite 按钮 | 现有 `LessonMarkdown`、`FrameworkTabs`、`BrowserRunButtons` |

- **AI 助教**：每段右下角放一个「问助教」按钮，自动带上当前段落和实验状态作为上下文（复用 `TutorChat`）。前提是服务端提供默认模型（见 §6 P1）。
- **进度**：①⑤⑥ 完成后写入 `progress`（`item_type = experiment | task | quiz`），复用现有进度表。
- **术语上限的检查方式**：在 overlay 的 frontmatter 里写 `newTerms: [..]`，CI 检查数量 ≤ 2。

### 4.1 `<Experiment>` 外壳组件（通用、可复用）

```
<Experiment
  demo="perceptron"                // 选现有 Demo
  preset="two-clusters"            // 预设数据
  intro="点「下一步」，看这条线会怎么动。"   // 只给一句任务说明，不含术语
  tasks={[
    { id:"separate", text:"让线把蓝点和橙点完全分开", check:"accuracy==1" },
    { id:"intruder", text:"在蓝点群里放一个橙点，再训练", check:"pointsAdded>=1 && steps>=10" },
  ]}
  aha="线总是被「站错边」的点拽过去"   // 完成后弹出的顿悟卡
/>
```

要实现这个外壳，每个 Demo 需要统一改造：接受 `preset`、`lockedControls`（隐藏暂时不需要的按钮）、`onState(state)` 回调，外壳根据回调的状态判断任务是否完成。

## 6. 改写样课：微课 1.1「画一条线把两类分开」（改写自第 03 课 感知机）

> 下面就是学习者在页面上看到的内容（中文）。方括号【】里的是给开发的交互说明。

---

### 🧪 先玩一下（3 分钟）

> **任务：点「下一步」，看看这条线会怎么动。**

【实验区：复用 `PerceptronDemo`，用 `<Experiment>` 包起来】
- 画布 360×360，预设 `two-clusters`：左下 12 个 **蓝点**，右上 12 个 **橙点**，两团之间有空隙。
- 初始直线**故意放歪**：先用固定初始权重 `w = [0.3, -0.8, 0.6]`（bias, x, y），让大约一半的点站错边。
- 站错边的点**闪烁并带红圈**。
- 只显示两个按钮：**「下一步」**、**「自动播放」**。学习率、权重数值、重新采样等控件先隐藏（`lockedControls`）。
- 每按一次「下一步」：按顺序取下一个点；如果它站错边，就用 0.4 秒动画把线从旧位置**转到**新位置，并从这个点画一条短箭头指向线的移动方向（表示「拽了一下」）。
- 右上角只显示一行：**「站错边的点：7 个」**。不显示「准确率」「epoch」这类词。

完成条件：站错边的点变成 0 → 弹出 ✅「分开了！」，同时解锁下一段。

---

### 🤔 你看到了什么？

**每次线动起来之前，发生了什么？**
- A. 线随机乱跳
- B. 有一个站错边的点被选中，线就朝它挪了一下 ✅
- C. 所有点一起推线

> 解析：只有**站错边**的点会让线动；站对了的点，线就不理它。

【`<ObserveQuestion>`：选错时提示「再按一次『下一步』，盯着闪红圈的那个点」】

---

### 💡 发生了什么（大白话）

想象你在操场上用一根绳子把男生和女生分成两边。一开始绳子放歪了，有几个男生站到了女生那边。你的做法很简单：**哪个人站错了，就把绳子朝他那边挪一点，直到他回到正确的一侧。** 一个一个处理下去，绳子最后就会停在一个能把两边分开的位置。

刚才电脑做的就是这件事：它没有被告知「线应该画在哪」，只是**一次次被站错的点纠正**，最后自己找到了位置。

---

### 🏷️ 给它起个名字

> **感知机**：一种「用一条直线把东西分成两类」的最简单的 AI。它靠**站错边的例子**一点点把线挪对。（1957 年就发明了，是今天所有神经网络的祖先。）

> **学习率**：每次挪线**挪多少**。挪得太少，学得慢；挪得太多，会来回甩。

【`<TermCard>` × 2；术语卡里的「站错边的例子」高亮，点击会让上面实验里站错边的点再闪一次】

---

### 🎮 再玩一次（5 分钟，3 个任务）

【`<Experiment>` 任务模式：现在显示「学习率」滑杆和「加蓝点 / 加橙点」按钮】

1. ☐ **调学习率**：把学习率拖到最大（1.0），点「自动播放」。
   观察：线是不是来回甩？再拖回 0.1 试试。
   【检查条件：`lr >= 0.9` 时至少跑了 10 步，之后又在 `lr <= 0.2` 时跑过 10 步】

2. ☐ **当一回捣乱分子**：在蓝点群的正中间放一个**橙点**，再自动播放。
   观察：线还能把所有点分开吗？
   【检查条件：`pointsAdded >= 1` 且 `steps >= 20`。完成后提示：「真实数据里总有几个『怪例子』，所以准确率很难到 100%」】

3. ☐ **不可能的任务**：点「换一组数据：四角棋盘」（预设 `xor`：左上、右下是蓝点，右上、左下是橙点），自动播放 30 步。
   观察：线能把它们分开吗？
   【检查条件：`preset == 'xor'` 且 `steps >= 30`。站错边的点永远 ≥ 1】

> 🎯 **顿悟**：一条直线，**怎么转都分不开**这种棋盘格。那该怎么办？→ 下节课 1.4 我们会让线「弯」起来。

### ✅ 小测（3 题，带解析）

1. 感知机什么时候会调整那条线？
   - A. 每个点都调一次
   - **B. 遇到站错边的点时** ✅
   - C. 只在最后调一次

   解析：站对的点不会产生调整，这正是「从错误中学习」。

2. 把学习率调得很大，最可能出现什么情况？
   - A. 一步就学好了
   - **B. 线来回甩，很难停稳** ✅
   - C. 线完全不动

   解析：每步挪得太多，就会冲过头。这和你在任务 1 里看到的一样。

3. 下面哪组数据，感知机**不可能**完全分对？
   - A. 蓝点全在左边，橙点全在右边
   - **B. 四角棋盘（对角同色）** ✅
   - C. 蓝点在下，橙点在上

   解析：感知机只会画**一条直线**，棋盘格需要弯的边界或两条线。

### 📌 一句话小结

> 感知机 = 一条会被「站错边的点」推着走的直线；学习率决定每次推多远；**一条直线分不开棋盘格**。

**下节课要解决的问题**：如果数据像棋盘格那样，怎么让分界线弯起来？

### 📚 进阶（默认折叠）

<details>
<summary>用数学写出刚才的过程（选读）</summary>

- 一个点 \(x=(x_1,x_2)\)，感知机计算 \(z = w_0 + w_1x_1 + w_2x_2\)。\(z\ge0\) 判为蓝（+1），否则判为橙（−1）。直线就是 \(z=0\)。
- 一个点站错边时更新：\(w \leftarrow w + \eta\, y\, x\)。\(y\) 是正确答案（±1），\(\eta\) 是学习率。这就是你在实验里看到的「朝那个点挪一下」。
